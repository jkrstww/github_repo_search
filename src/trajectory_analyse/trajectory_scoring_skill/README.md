### 2.初始迭代提示词模板
**iterated_rubric/base_0.yaml + iterated_prompt.j2**

1. 从 base.yaml 剥离所有 score 权重和 positive/negative examples，只保留维度/子维度的 description 与 score_rules，作为 prompt 自演化迭代的起始模板
2. LLM 对每个子维度逐条判定 score_rules，输出 0~1 分（细则通过率，四舍五入到两位小数）与 reasoning，以及逐条 verdict
3. 汇总口径：维度分 = 子维度 0~1 分的均值（每维 0~1），总分 = 六个维度分的均值（0~1）；迭代流程中不使用汇总分数做任何决策

### 3.rubric 迭代（iterate_base_rubric.py）

以 `iterated_rubric/base_0.yaml` 为起点做 prompt 自演化

**逐轨迹增量迭代**：

for 每条采样轨迹 (30 条依次处理):
    ① 打分（当前 rubric，6 维并发 + 补打循环；全失败→跳过决策）
    ② 立即决策（train 模板，1 次调用）：
       输入 = 当前 rubric + 本轨迹打分结果 + 原始轨迹 + 前面已处理轨迹的指标历史分数
       输出 = {needs_modification, analysis, edits}
       ├─ 不需要修改 → 本条结束，处理下一条
       └─ 需要修改 → 应用 edits → ③ 软质量审查
            ├─ 不合格 → 沿用旧版
            └─ 合格 → ④ 从 verified_dataset 随机抽 1 条，新旧 rubric 各打一次分 →
                      ⑤ LLM 比较两版 reasoning
                 ├─ 更合理 → 采纳，后续轨迹用新 rubric 继续打分
                 └─ 否则 → 保留旧版

### 4.迭代结果

**迭代 1**（一次性聚合架构，seed42，30 条 gpt-5-2-high 轨迹）——聚合分析发现的核心问题：
- B2 因果实验：多条 review 反复接近 0 分——静态分析经常已足够，强制受控实验是稀少特例
- F3 总结与轨迹一致性：轨迹中没有“最终总结”的环节
- C4 实现代码质量：捆绑 4 个独立判断（无关文件/重复逻辑/宽泛异常/范围扩张）
- C1/D1/D2：隐含 bug-fix 语境，在 feature-addition 轨迹上系统性失败；改为同时覆盖缺陷修复和新增功能
- F1/F2：强制 git diff HEAD 等特定命令与任务指令冲突，改为意图导向（确认 diff 完整内容、检查工作树状态）

rubric 变化：22 → 20 个 subcriteria（删 B2、F3），89 → 84 条规则，C1/C4/D1/D2/F1/F2 六个指标的规则被改写；没有新增指标。
